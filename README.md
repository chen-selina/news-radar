## 最快的方式：點兩下 `start_site.bat`

只想把網站打開的隊友，做這兩步就好：

1. 安裝 [Python](https://www.python.org/downloads/) 3.11 以上，安裝時勾選「Add python.exe to PATH」。
   （Microsoft Store 版或沒勾 PATH 的話，啟動檔會找不到 Python。）
2. 從 GitHub 按「Code → Download ZIP」下載後，**先在 ZIP 上按右鍵「解壓縮全部」**，不要在壓縮檔裡面直接點。
3. 進到解壓縮後的資料夾，點兩下 `start_site.bat`。
   如果跳出藍色的「Windows 已保護您的電腦」，點「其他資訊」→「仍要執行」（Windows 對網路下載的 `.bat` 都會這樣問）。

第一次會自動安裝需要的套件、下載上市櫃公司清單（需要網路，約幾分鐘），完成後瀏覽器會自己打開。
之後再點就只要幾秒。失敗時黑色視窗會停住並顯示原因，請截圖給團隊。

- **不要把別人電腦的 `.venv` 資料夾複製過來用**：它記著原本那台電腦的 Python 位置，換一台就壞了。
  `start_site.bat` 發現 `.venv` 不能用時會自動刪掉重建，所以整個資料夾壓縮傳給隊友也沒關係。
- 新電腦的資料庫是空的，網站打開後沒有新聞是正常的，按「重新爬取新聞」或執行 `run_jobs.bat` 就會有。
- 如果顯示 8000 埠被占用，改用 `start_site.bat --port 8001`。

## 載入上市櫃公司

```bat
python -m radar.stocks.load
```

會從證交所與櫃買中心的官方 OpenAPI 下載公司基本資料與收盤價，寫進 `data/radar.db`（約 2,000 家）。
資料庫不進版控，每位隊友在自己電腦跑一次即可；公司有新上市、下市時重跑一次。

| 資料 | 來源 |
|---|---|
| 上市公司基本資料 | `openapi.twse.com.tw/v1/opendata/t187ap03_L` |
| 上櫃公司基本資料 | `www.tpex.org.tw/openapi/v1/mopsfin_t187ap03_O` |
| 上市收盤價 | `openapi.twse.com.tw/v1/exchangeReport/STOCK_DAY_ALL` |
| 上櫃收盤價 | `www.tpex.org.tw/openapi/v1/tpex_mainboard_daily_close_quotes` |

其他選項：

- `--save-raw data\raw`：順便把官方原始 JSON 存檔
- `--from-raw data\raw`：不連網，用存檔的 JSON 載入
- `--db 路徑`：改用別的資料庫檔

### 公司詞典怎麼組成

| 欄位 | 來源 |
|---|---|
| 名稱、全名、上市／上櫃、官方產業別、股數 | 官方資料 |
| 市值 | 股數 × 最近收盤價。**產業連動每個族群取市值最大的前 4 檔** |
| 別名 | 自動去掉「-KY」「*」後綴（臻鼎-KY → 臻鼎），加上 `config/stock_overrides.json` 的人工別名 |
| 細分族群（記憶體、AI伺服器、CPO…） | `config/stock_overrides.json`，人工維護 |

`stock_overrides.json` 目前是原型裡的 59 檔，要補其他公司的族群或別名，直接在這個檔加一行，例如：

```json
"2337": {"name": "旺宏", "aliases": [], "sectors": ["記憶體"]},
```

改完重跑 `python -m radar.stocks.load`。如果寫的代號不存在，或 `name` 跟官方簡稱不同，載入時會顯示「注意」提醒。

## 爬取新聞

```bat
python -m radar.crawl
```

依 [`config/crawl.json`](config/crawl.json) 的開關爬取各來源，每個來源最多 30 則，存進 `data/radar.db`。

- `--source cw`：只抓某個來源，可重複指定（例如 `--source bw --source cw`）
- `--limit 5`：每個來源最多幾則
- `--dry-run`：只列出會收錄的新聞，不存檔

| 來源 | 抓取方式 | 模組 |
|---|---|---|
| Yahoo奇摩股市 | 台股 RSS `tw.stock.yahoo.com/rss?category=tw-market` | `radar/crawl/sources/yahoo.py` |
| Google新聞 | 「台股」搜尋 RSS（**預設關閉**，見下方） | `radar/crawl/sources/google.py` |
| 經濟日報 | 證券 RSS `money.udn.com/rssfeed/news/1001/5590/5607` | `radar/crawl/sources/udn.py` |
| 商業周刊 | 財經頻道列表頁（只收 `/business/blog/`，`/indep/` 是廣編稿不收） | `radar/crawl/sources/bw.py` |
| 天下雜誌 | 「今日最新」列表頁（**預設關閉**，見下方；帶 `?rec=` 的推薦舊文不收） | `radar/crawl/sources/cw.py` |

網站改版時，列表的網址與規則改各來源的模組；文章內文擷取的區塊改 `radar/crawl/extract.py` 的 `BODY_SELECTORS`。

**爬取規則**

- 每個網址先檢查 robots.txt（`radar/crawl/robots.py`），不允許的不讀；同一網站兩次請求至少間隔 1.5 秒。
- 沒有原文網址的不收錄。網址會先去掉追蹤參數（`utm_`、`rec` 等）再當唯一鍵。
- 去重：網址相同，或 3 天內標題相同（忽略空白與標點）視為同一則。
- 內文最多存 3,000 字，只供分析。讀不到內文時改用 RSS／網頁摘要，再不行就只用標題分析；
  `news.body_from` 記錄是哪一種（page／summary／title）。網頁標示非免費閱讀時 `paywalled = 1`。
- 文章頁暫時連不上又沒有摘要時先不存，下次爬取會重試。

**Google新聞為什麼暫停**：news.google.com 的 robots.txt 不允許一般程式讀取 `/rss/`；而 Google 的連結
是轉址，2024 年後的新格式必須再向 Google 查詢才能得到原始網址，同樣被 robots.txt 禁止。
程式已經寫好（舊格式可以不連網解出原始網址），要啟用請先決定如何處理 robots.txt，再改 `crawl.json`。

**天下雜誌為什麼暫停**：robots.txt 允許爬取，但網站對本爬蟲回應 403（拒絕存取），在兩台電腦上結果相同。
專案決定不改 User-Agent 繞過網站阻擋；天下的文章可以用「貼連結分析」手動加入。

## 公司短名稱的排除規則

全市場有一千多家公司的簡稱只有兩個字，很容易撞到一般用詞或跨詞誤判，
例如「大量賣單」→ 3167 大量、「投信大買」→ 1109 信大、「東南亞」→ 1303 南亞、「工商時報」→ 8923 時報。

所以**兩個字的公司名要有佐證才算**，任一項成立即可：

| 佐證 | 例子 |
|---|---|
| 旁邊有股票代號 | 能率（5392）、2468 華經 |
| 用括號標出 | 【精測】、「欣銓」 |
| 用頓號與其他公司並列 | 旺宏、力成下午舉行法說會 |
| 後面緊接股市用語（營收、股價、法說、漲停、逆勢…） | 台玻逆勢、尖點 9 月營收 |
| 前面緊接股市用語（點名、調節、買超、○○廠、外資…） | 調節友達、鑽針廠尖點 |
| 同一則新聞已確認過這家公司 | 前面有「南紡（1440）」，後面的「南紡」也算 |

不需佐證：三個字以上的名稱、`trusted` 名單（市值較大且不易混淆的 158 家，例如鴻海、聯電、華碩）、
`stock_overrides.json` 的人工別名（台積、虎航）。`exclude_phrases` 裡的片語（東南亞、統一化…）一律不算。

全部設定在 [`config/name_rules.json`](config/name_rules.json)，程式在 `radar/analysis/names.py`。
這套規則是原型沒有的：與原型比對的測試不使用它，正式流程會使用（見下一節的 `production_analyzer()`）。

## 產業連動只看關鍵字所在句子

原型的做法是：產業關鍵字所在的句子沒有情緒時，改用**整則新聞的總分**。結果生活新聞裡隨口一提的詞也會連動，
例如甜甜圈店新聞「有人拿起**手機**拍下來」讓手機族群 +1.0、ETF 新聞「績效集中在**半導體**產業」讓晶圓代工族群 +6.5。

正式版改成：**只用關鍵字所在句子的情緒；句子沒有情緒就不連動。只有關鍵字出現在標題時，才退回用整則總分**
（標題通常就是整篇的主題，例如「機器人、記憶體題材熱夯」）。

以約 240 則新聞試算，產業連動從 37 組降到 27 組，原型的 15 則範例新聞不受影響。
設定在 `radar/analysis/engine.py` 的 `sector_fallback`（`"total"`＝原型、`"title"`＝正式版）。

正式流程（爬蟲建立預測、`python -m radar.analysis`）用 `production_analyzer()` 建立分析器，
會同時開啟這項修正、公司短名稱排除規則，以及下一節的三項修正；與原型比對的測試全部不開。

## 2026-11-10 的三項修正（詞典第 2 版起）

檢查 68 則實際新聞後發現原型規則在真實新聞上的三個問題，各加一個開關（`radar/analysis/engine.py`）：

| 開關 | 原型 | 正式版 | 解決什麼 |
|---|---|---|---|
| `repeat_decay` | 1：同一個詞出現幾次加幾次 | 0.5：第 2 次算一半、第 3 次算四分之一… | ETF 說明文因「配息」出現 13 次得到 +13 |
| `direct_scope` | `sentence`：公司拿整句的分數 | `segment`：一句有多家公司時依逗號分段，各拿各的；沒提到公司的子句歸給前一家 | 「群創遭賣超，台玻獲買超」兩家互相抵銷或同分 |
| `direct_fallback` | `total`：提到公司的地方沒有情緒詞，取總分一半 | `title`：公司在標題才這樣做，否則 0 分（中性，不計入命中率） | 「漲幅前 5 名個股為…」因為整則偏空而全部被判偏空 |

同時詞典改為第 2 版：補上 32 個常見漲跌用語（大漲、勁揚、走高、月增、月減、倒貨、調節、翻黑…），
「配息」停用，「訂單、量產、壓力」分數減半。

預測只記錄詞典版本，沒有另外記錄引擎版本：**詞典第 1 版的預測用舊規則，第 2 版起用新規則**。
之後再改引擎規則時，請同時讓詞典產生新版本（或在 `predictions` 加欄位記錄），才分得出來。

**下一步是機器學習**（2026-11-10 決定）：詞典改當特徵來源，累積到幾千筆已驗證的樣本後，
先用邏輯迴歸、再用 LightGBM／XGBoost 學每個詞的權重，並加入股價、成交量等特徵。
驗證要按時間切分（前面幾個月訓練、後面測試），同一事件的多則新聞要去重。詞典版保留當基準。

## 預測鎖定

`python -m radar.crawl` 每存一則新聞，就**立刻**用當時的詞典分析，把結果存進 `predictions`
（總分、利多／利空／中性、詞典版本）與 `prediction_stocks`（每檔個股的分數、方向、直接提及或產業連動、判斷理由）。

- 每則新聞只有一筆原始預測。資料庫觸發器會擋住修改、刪除，也不能事後追加個股（`radar/db.py`）。
- 之後改詞典，舊預測完全不受影響；預測記錄的詞典版本可以用 `lexicon.get(conn, 版本)` 還原。
- 爬取時沒能建立預測的新聞（例如還沒載入公司資料），下次爬取或執行下面指令時會補建：

```bat
python -m radar.predict
```

想看新詞典對舊新聞的效果，用「重算」，結果另外存在 `recalcs`／`recalc_stocks`，不碰原始預測：

```bat
python -m radar.predict --recalc
```

## 收盤價

```bat
python -m radar.prices update
```

從最早一則新聞的前一個月抓到今天，已抓過的日子會跳過；每天收盤後跑一次即可補上當天。

| 資料 | 來源 |
|---|---|
| 交易日曆＋加權指數 | 證交所 `FMTQIK`（一次一個月；只列實際開市日，國定假日、颱風休市自然排除） |
| 上市個股收盤價 | 證交所 `MI_INDEX`（一次一天、全部上市股票） |
| 上櫃個股收盤價 | 櫃買中心 `afterTrading/otc`（一次一天、全部上櫃股票） |

證交所請求太密集會暫時封鎖，所以同網站請求間隔 3.5 秒（`radar/config.py` 的 `HOST_INTERVALS`），
第一次抓一個多月的資料約需 3 分鐘。官方當天資料還沒公布時會顯示「下次再試」。

- `--from 2026-09-01`、`--to 2026-10-27`：指定日期範圍
- 也可以匯入自己的收盤價 CSV（欄位：日期, 代號, 收盤價；日期可用民國年；大盤代號寫 `TAIEX`、加權指數或大盤）：

```bat
python -m radar.prices import 收盤價.csv
```

## 預測驗證

```bat
python -m radar.validate
```

預設看第 3 個交易日、扣除大盤、持平門檻 ±1%。選項：`--horizon 1/3/5/10`、`--raw`（個股漲跌）、
`--threshold 2`（門檻 2%）、`--direct`（只看直接提及的個股）、`--recalc 2`（改用第 2 版詞典的重算結果）。

| 規則 | 說明 |
|---|---|
| 基準價 | 09:00 開盤前發布取前一個交易日收盤；開盤後發布（盤中與盤後）取當日收盤（當日休市取之前最後一個交易日）；沒有時間視為盤前 |
| 第 N 日 | 以證交所實際交易日計算 |
| 實際方向 | 報酬（預設扣除加權指數報酬）高於門檻為漲、低於負門檻為跌，其餘持平 |
| 命中 | 預測利多且實際漲，或預測利空且實際跌；中性預測不計入 |
| 待驗證 | 未滿 N 個交易日顯示「等待 N 日」；新聞當天收盤價還沒出來顯示「等待基準價」 |

輸出包含：整體／利多／利空命中率與筆數、多空報酬差、低／中／高影響程度各自的命中率、
新聞前 3 日到後 10 日的平均累積報酬（事件研究圖的資料）、逐筆結果。
網頁透過 `GET /api/validation` 取得同一份結果（`radar/validate.py` 的 `validate()`）。

### 為什麼盤中新聞用當日收盤當基準

2026-11-13 以前，基準價以 13:30 收盤為界（與原型相同）：盤中發布的新聞用前一日收盤當基準，「第 1 日」就是當天收盤。
但盤中新聞常常是在報導當天已經發生的漲跌（10:18 的「奇鋐亮燈漲停」），這樣算等於拿結果來驗證結果。
用回補的 2,908 篇新聞實測（手工詞典、第 1 日）：盤中新聞命中率 57%、多空報酬差 +4.5%；盤前與盤後的新聞只有 41%、+1.3%。

現在改成以 09:00 開盤為界：開盤後才出來的消息，從當日收盤後開始算。只有每日收盤價（沒有盤中價格）時，這是避免偷看答案的做法。
這個修改只影響驗證怎麼算，已鎖定的預測內容沒有變；網站上的命中率會比修改前低，那是比較接近實際的數字。

### 同事件新聞不重複計算

同一件事常被很多家媒體報導（2026-11-10 台積電董事會的配息與投資案，88 則新聞裡就占了 14 則）。
每則各算一筆的話，這一件事猜對或猜錯會被算成 14 次，命中率會失真。

```
python -m radar.validate --dedupe
```

加上 `--dedupe`（網頁「計算單位」選「每檔每日」）後，改成**一檔個股、一個基準交易日只算一筆**：

1. 這檔個股當天有被直接提及，就不看產業連動的那幾筆。
2. 同一事件的多篇報導只取分數絕對值最大的一篇。
3. 當天不同事件的分數取平均，再依平均分數判斷利多、利空、中性。

「同一事件」由 `radar/dedupe.py` 判斷：標題去掉標點與媒體名稱後切成相鄰兩字的組合，
兩則共有的組合數 ÷ 較短那則的組合數 ≥ 0.5（且至少共有 4 個），發布時間相差 36 小時內，就視為同一事件；
互相連得到的併成一群。只比標題，用字完全不同的同一件事會漏掉。

以個股、交易日為單位彙整新聞情緒，是新聞情緒研究常見的做法；預設仍是每則新聞各算一筆，方便逐則檢查。
`python -m radar.compare` 預設就用每檔每日，加 `--per-news` 可改回每則新聞。

## 字典比較：手工詞典與論文字典

手工詞典（`config/lexicon-handmade.json`）的詞和分數是自己訂的，沒有文獻依據。為了讓方法有出處，專案另外收了一部公開的學術字典：

> 黃裕烈 (2025)，〈台灣財經情緒字典與議題分類字詞之編製與應用：大型語言模型之協作與分類評估〉，《經濟論文》。
> 資料：<https://github.com/RemiMFB/Taiwan-Financial-Sentiment-Dictionary>（CC BY 4.0）

轉檔後放在 [`config/remi/`](config/remi/README.md)：主字典 7,741 個詞（正面 3,444、負面 4,297），以及景氣、貨幣政策、利率、匯率、物價五個議題的分類字詞。
字典每年 3 月改版，改版後用 `python tools/import_remi.py "解壓縮後的資料夾/data"` 重新轉檔。

論文驗證的是央行新聞稿與總體經濟變數，沒有驗證個股股價，而且字典裡沒有「漲停」「賣超」「營收成長」這類個股事件詞。
所以這裡用同一批新聞、同一份收盤價，比較三個版本：

| 版本 | 內容 |
|---|---|
| 手工詞典 | `config/lexicon-handmade.json`，每個詞有人工給的強度（−2.5～+2） |
| 論文字典 | 只用論文字典，每個詞 ±1（論文的用法：只數詞，沒有強度） |
| 論文＋個股擴充 | 論文字典加上手工詞典的個股事件詞，一律 ±1；兩邊方向不同的詞（「吃緊」）以手工詞典為準 |

三個版本的歸屬規則（哪一句算給哪家公司、產業連動、否定反轉、標題加權）完全相同，差別只有字典。

```
python -m radar.compare
python -m radar.compare --all --raw --threshold 2
```

預設只看直接提及的個股、扣除大盤、門檻 ±1%；`--all` 連產業連動一起算。每個觀察期間列出命中率、利多與利空之後的平均報酬、多空報酬差，
方括號裡是這批個股實際漲、跌的比例（亂猜的命中率大約就是這個數字）。這個指令只讀資料庫，不會寫入。

`radar/analysis/remi.py` 另外提供 `count()`（正面、負面詞數）與 `tone()`（論文式 (1) 的情緒指標），之後做機器學習時當特徵用。

**解讀時要注意**：已驗證筆數不到 300 筆時，指令最後會提醒差距可能只是運氣。即使超過，如果新聞集中在少數幾天，
同一天的個股會一起漲跌，實際的獨立樣本遠比筆數少，要累積很多個交易日才能下結論。

## 在命令列執行指令：用 `run`

這份文件裡的 `python -m radar.xxx` 都要用專案自己的 Python（`.venv`）執行。直接打 `python` 會用到電腦上另一個 Python，
出現 `ModuleNotFoundError: No module named 'httpx'` 這類找不到套件的錯誤。在專案資料夾裡改用 `run` 就不會弄錯：

```

run backfill --status
run compare --backfill
run validate --dedupe
```

## 回補歷史新聞（訓練與回測用）

平常的爬蟲只讀各網站的「最新新聞」列表，每天幾十則，要累積好幾個月才夠訓練。回補工具把過去的新聞（含內文）抓回來：

1. **查網址**：向 [FinMind](https://finmindtrade.com)（開放的台股資料平台）查「某檔個股、某一天」有哪些新聞，拿到標題與原文網址。
2. **抓內文**：逐篇讀原文網頁，規則和平常的爬蟲相同：先看該網站的 robots.txt、同網站請求間隔 1.5 秒、不偽裝身分。

最簡單的方式是點兩下 `backfill.bat`（市值前 20 檔、最近 90 天），等同：

```
python -m radar.backfill --top 20 --days 90
python -m radar.backfill --status                 看進度與各網站的成功率
python -m radar.backfill --codes 2330,2454 --from 2026-09-01 --to 2026-09-30
python -m radar.backfill --fetch-only --limit 200 只抓內文，最多 200 篇
```

- **可以隨時按 Ctrl+C 中斷**，每查一天、每抓一篇都會存檔，下次執行接著做。
- **FinMind 一次只能查一檔一天**，免費每小時 300 次。到上限時工具會先去抓內文，抓完再每 10 分鐘試一次。
  前 20 檔 90 天約 1,800 次查詢，要 6 小時左右。到 FinMind 網站註冊後把金鑰放進環境變數 `FINMIND_TOKEN`，上限提高到每小時 600 次。
- **會略過的網址**：Google新聞的轉址連結（大約 2025 年下半年以前的資料都是這種，Google 的 robots.txt 不允許程式讀取）、
  討論區貼文與個股資訊頁（不是新聞）。
- **某個網站連續 5 篇讀不到**，這次執行就不再讀它；確認是擋程式的網站（被拒絕 HTTP 403 至少 5 篇、而且比讀到的多，
  例如中時新聞網），之後都標成略過，不再嘗試。`--status` 會列出每個網站的成功率與平均內文字數。
- **內文後面夾帶的東西**：通用規則常把「延伸閱讀」的其他新聞標題和站內廣告一起抓進來。分析時用 `clean_body()` 去掉
  （第 3 段以後出現「延伸閱讀」「上一篇」「下載APP」等字樣的段落起全部不算，結尾沒有句號的段落不算）；資料庫保留原樣。
  2026-11-13 試跑時平均每篇從 1,038 字減為 900 字。ETtoday、TVBS 的結尾仍會殘留少量無關文字。
- 標題用 FinMind 給的（有些網站的網頁標題其實是分類名稱）。
- 自由財經股市頻道、聚財網、台視等網站只讀得到標題或摘要（約占一成），這些不納入比較。
- 內文擷取只針對 Yahoo、經濟日報、商周調整過，其他網站用通用規則（中文字 25 字以上的段落），可能夾雜選單或廣告文字。
  試跑後先看 `--status` 的平均字數與資料庫裡的內文，再決定要不要擴大範圍。

資料存在 `backfill_news`、`backfill_tags`、`backfill_days` 三張表，**和網站用的 `news` 分開**：回補的新聞是事後抓的，
沒有「收錄當下鎖定」的預測，不會出現在網站的新聞列表與預測驗證裡，只用來訓練與回測：

```
python -m radar.compare --backfill
```

新聞內文是各媒體的著作，只留在自己電腦的 `data/radar.db`（不進版控），不要另外公開散布。

## 由資料估計情緒詞的權重

手工詞典的分數（飆漲 +2、大漲 +1.5）是憑感覺給的，論文字典則完全沒有強度。`radar/train.py` 用邏輯迴歸
（logistic regression）從資料估計：每個詞一個係數，正的代表這個詞出現之後股價（扣除大盤）傾向漲。

```
pip install -r requirements-ml.txt        第一次要先裝 numpy、scikit-learn（網站本身不需要）
python -m radar.train                     回補的新聞、第 1 個交易日
python -m radar.train --horizon 3 --min-count 20
```

| 項目 | 做法 |
|---|---|
| 樣本 | 一檔個股、一個基準交易日一筆（同事件的多篇報導只取一篇，不同事件取平均） |
| 特徵 | 這檔個股被直接提及的範圍裡，每個情緒詞的出現次數；否定算負的，標題、加強詞有加權（同分析引擎）。詞來自「論文字典＋個股擴充」 |
| 標籤 | 第 N 個交易日扣除大盤後的報酬：超過 +1% 為漲、低於 −1% 為跌，中間的不用 |
| 納入的詞 | 在訓練期至少出現 15 筆（`--min-count`） |
| 切分 | **依時間**：最後三成交易日留作測試，完全不參與訓練；正則化強度也只在訓練期裡挑 |
| 比較基準 | 全猜訓練期較多的那一邊；不估權重、每個詞 ±1 加總 |

依時間切分是重點：隨機切分會讓同一天、同一事件的新聞同時出現在訓練和測試，準確率會虛高。
模型在測試期贏不過兩個基準，就代表估出來的權重沒有用。

結果存在 `data/weights-h{N}.json`（不進版控），**不會改動 `config/lexicon.json`**，也沒有套用到正式預測（2026-11-14 實測贏不過「全部猜跌」）。

2026-11-13 第一次試跑（回補到一半，20 個交易日、1,493 筆）：模型測試期準確率 55%，全猜跌 57%，字典加總 51%。
也就是還沒有贏過基準，權重也不合理（「重挫」是正的、「大漲」是負的），這是資料太少、又集中在暴跌後強彈那幾天的結果。
交易日不到 40 個時指令會提醒；要等回補跑完再看。

## 開啟網站

```bat
python -m radar.api
```

用瀏覽器打開 http://127.0.0.1:8000 就是網站。按 Ctrl+C 停止。
平常最快的方式：直接點兩下 `start_site.bat`，會啟動網站，等網站準備好就自動打開瀏覽器（`python -m radar.api --open`）；網站已經開著時，再點一次只會打開瀏覽器，不會重複啟動。
想更方便：在 `start_site.bat` 按右鍵 →「顯示其他選項」→「傳送到」→「桌面（建立捷徑）」，之後點桌面圖示即可。
排程（爬新聞、抓收盤價）不需要網站開著。
預設只有自己的電腦連得到；要讓同一個網路的隊友連進來，加 `--host 0.0.0.0`。

畫面沿用原型 `news-radar.html`，但所有資料都來自資料庫（透過下面的 API）：

| 分頁 | 和原型不同的地方 |
|---|---|
| 最新新聞 | 顯示資料庫裡的新聞與**鎖定的預測**（不會因為改詞典而變）。多了期間選擇（今天／近 3、7、30 天／全部）、「載入更多」；搜尋也會比對受影響個股的代號與名稱。「重新爬取新聞」真的會去爬（約需數分鐘）；進站會自動爬、之後有新新聞會在按鈕上提醒（見下方） |
| 貼連結分析 | 由伺服器讀網頁（不再借用 Claude 桌面版的瀏覽器），任何瀏覽器都能用。讀不到時說明原因，可手動貼上內文。「加入新聞列表」會存進資料庫並鎖定預測 |
| 情緒詞典 | 新增、改分數、刪除會改 `config/lexicon.json` 並建立新版本，所有人共用；顯示版本紀錄 |
| 預測驗證 | 用真實收盤價，拿掉模擬的示範資料與新聞 CSV 匯入（新聞來自爬蟲）。可切換「原始預測」或「第 N 版詞典重算」比較詞典修改的效果；可抓最新收盤價或匯入收盤價 CSV |

**進站自動爬取與新新聞提醒**

- 打開網站（或重新整理）時，會先看各來源的列表有沒有還沒收錄的新聞，**有就自動開始爬**，不用自己按。
- 網站開著的期間每 10 分鐘再看一次。有新的**不會自動爬**，而是在「重新爬取新聞」按鈕右上角顯示紅色數字、
  旁邊顯示「有 N 則新新聞」；滑鼠移到按鈕上可以看到標題。按下去爬完，數字就會消失。
- 這個檢查只讀列表（每個來源一次請求，不讀文章頁），結果保留 10 分鐘，所以多開幾個分頁或一直重新整理，
  也不會更常連到新聞網站（`GET /api/crawl/check`，間隔是 `radar/api/app.py` 的 `CHECK_TTL_SECONDS`）。
- 排程正在跑的時候不檢查，顯示「排程正在爬取中」。
- 這不能取代排程：網站沒開的時候不會爬，新聞過了一兩天就抓不到了。

網頁檔案在 `web/`（`index.html`、`app.js`、`style.css`），改完重新整理瀏覽器即可，不需要重新啟動。

## 排程

PROJECT_BRIEF 要求每天 **08:00（開盤前）** 與 **14:30（收盤後）** 各跑一次。我們用 **Windows 工作排程器**，
每次執行 `run_jobs.bat`，也就是 `python -m radar.jobs`：

1. 爬新聞，存檔的同時鎖定預測（等於 `python -m radar.crawl`）
2. 抓收盤價，只抓還沒有的交易日（等於 `python -m radar.prices update`）

預測驗證在網站打開時即時計算，收盤價一進資料庫，驗證結果就跟著更新，不需要另外排程。

### 設定（一次就好）

```bat
tools\schedule_windows.bat
```

會建立兩個工作「TWNewsRadar 0800」「TWNewsRadar 1430」。可以在「工作排程器」程式裡看到，或用指令確認：

```bat
schtasks /query /tn "TWNewsRadar 0800"
```

取消排程：

```bat
tools\unschedule_windows.bat
```

想立刻手動跑一次：

```bat
run_jobs.bat
```

### 要注意的地方

- **電腦要開著、不能睡眠**。錯過的那次不會補跑；不過下一次會補上缺的收盤價，
  RSS 和列表頁通常也保留一兩天的新聞，偶爾錯過一次影響不大。
- **時間以電腦的時鐘為準**，電腦時區要設成台北（UTC+8）。
- **14:30 那次常抓不到當天收盤價**：證交所、櫃買中心當天的資料通常下午才公布完整，
  抓不到會記為「部分完成」並註明「下次再試」，隔天 08:00 那次會補上。
- **執行紀錄**：
  - 輸出存在 `data/logs/jobs-年-月.log`。
  - 網站上方的「上次排程」顯示最近一次的結果，滑鼠移上去可以看摘要。
  - 「部分完成」代表有某個來源或某天的收盤價沒抓到，細節看 log。
- **同時只跑一個**：排程執行中會留下 `data/jobs.lock`。這時候再觸發排程會直接略過，
  網站的「重新爬取新聞」也會回覆「排程正在執行」。程式異常中斷留下的鎖檔（例如爬到一半關掉網站視窗）不會卡住：
  鎖檔記著建立它的程式編號，那個程式已經不在就立刻失效；另外超過 2 小時也會自動失效。
- 公司清單（新上市、市值）不在排程裡，建議每個月手動重跑一次 `python -m radar.stocks.load`。

### 其他作業系統

macOS／Linux 的隊友可以用 cron，例如（`crontab -e`，路徑換成自己的）：

```
0 8  * * * cd /path/to/news-radar && PYTHONIOENCODING=utf-8 .venv/bin/python -m radar.jobs
30 14 * * * cd /path/to/news-radar && PYTHONIOENCODING=utf-8 .venv/bin/python -m radar.jobs
```

### 為什麼不用 GitHub Actions 或 APScheduler

- **GitHub Actions**：資料庫 `data/radar.db` 存在自己電腦、不進版控，GitHub 的機器拿不到。
  如果改成每次把資料庫 commit 回 repo，鎖定的預測就會變成可以被任何人改寫的檔案，也會讓 repo 越來越大。
- **APScheduler**（排程寫在網站程式裡）：網站要一直開著才會跑。工作排程器不需要網站開著，電腦重開後也還在。

## 部署與協作

### 在自己電腦上使用

照「快速開始」做完即可。網站沒有登入功能，所以：

- 預設只有自己的電腦連得到（127.0.0.1）。
- 要讓**同一個網路**的隊友連進來，用 `start_site.bat --host 0.0.0.0` 啟動，隊友打開 `http://你的電腦IP:8000`。
  第一次會跳出 Windows 防火牆詢問，選「私人網路」。
- **不要開放到網際網路**：任何連得到的人都能改詞典、觸發爬蟲。

### 和隊友用 GitHub 共同開發

| 進版控（大家共用） | 不進版控（每個人自己的） |
|---|---|
| 程式（`radar/`、`web/`、`tests/`、`tools/`） | 資料庫 `data/radar.db`（新聞、鎖定的預測、收盤價） |
| 設定（`config/`：詞典、公司別名、爬取開關、排除規則） | 排程紀錄 `data/logs/`、鎖檔 |
| `.bat` 檔、README | 虛擬環境 `.venv/` |

- 每個人都有自己的資料庫，各自爬、各自鎖定預測。建議**指定一台電腦當正式資料**：只有它設定排程，
  命中率也以它為準。其他人的資料庫只用來開發、測試。
- **詞典版本號是各資料庫自己編的**：同一份 `config/lexicon.json`，在你的資料庫可能是第 3 版，在隊友那邊是第 5 版。
  兩邊內容是否相同，看 `lexicon_versions` 資料表裡的 `checksum` 欄位。
  在網站改詞典會修改 `config/lexicon.json`，記得 commit，隊友 pull 之後下次分析時會自動建立新版本。
- 改了程式的人請先跑 `python -m pytest`，全部通過再推上去。
- `.bat` 檔只能用英文（ASCII）並用 Windows 換行（CRLF），否則 cmd 會讀錯。
- `requirements.txt` 也只能用英文：舊版 pip 會用 Windows 的 Big5（cp950）讀它，裡面有中文註解就會在安裝時失敗
  （`UnicodeDecodeError: 'cp950' codec can't decode…`，2026-11-11 隊友實際遇到）。
  兩個 `.bat` 也設了 `PYTHONUTF8=1`，讓 Python 一律用 UTF-8 讀檔。

### 備份

最重要的資料是 `data/radar.db` 裡**鎖定的預測**：它們是「當下」的判斷，事後無法重建。
請定期把 `data/radar.db` 複製到別的地方（例如雲端硬碟）。複製前先關掉網站，並確認排程沒有在執行。

## 網站後端 API

網站啟動後，打開 http://127.0.0.1:8000/docs 可以看到所有 API 的說明，也能直接在網頁上按「Try it out」試用。

| API | 用途 |
|---|---|
| `GET /api/news?label=&source=&q=&stock=&since=` | 新聞列表，附上鎖定的原始預測與受影響個股；`label` 為 pos／neg／neu，`source` 多一個 `other`（其他網站）；`highlight=true` 附上原文要標色的關鍵詞位置 |
| `GET /api/news/summary?since=&source=` | 情緒分布與個股影響排行（網頁側欄） |
| `GET /api/news/{id}` | 單則新聞；另附原文上要標色的關鍵詞位置（用鎖定時的詞典版本重新標示，分數仍以鎖定的預測為準） |
| `POST /api/news` | 「加入新聞列表」：存檔並立刻鎖定預測。必須有原文網址；同一網址已存在回傳 409 |
| `POST /api/analyze-text` | 分析標題與內文，不存檔 |
| `POST /api/analyze-url` | 貼連結分析：後端讀網頁、擷取標題與內文後分析，不存檔 |
| `GET /api/validation?horizon=3&benchmark=excess&threshold=0.01&scope=all` | 預測驗證；加 `lexicon_version=` 改驗證該版詞典的重算結果，加 `dedupe=true` 改成一檔個股一天算一筆 |
| `POST /api/recalc` | 用目前的詞典重算所有新聞（另存，不改原始預測） |
| `GET／POST／DELETE /api/lexicon` | 看詞典與版本紀錄／新增或改分數／刪除（`?term=`）；每次修改都會建立新版本 |
| `POST /api/crawl` | 爬取新聞（會花幾分鐘；同時只能跑一個） |
| `GET /api/crawl/check` | 各來源有幾則還沒收錄的新聞（只讀列表、不存檔，結果保留 10 分鐘）；網站用它自動爬取與提醒 |
| `POST /api/prices/update`、`/api/prices/import` | 抓收盤價／匯入 CSV（開發用） |
| `GET /api/stocks?q=`、`GET /api/meta` | 搜尋公司；來源清單、詞典版本、資料筆數與價格資料範圍 |

錯誤一律回傳 `{"detail": "白話說明"}`。

**貼連結分析**讀不到內容時不會出錯，而是回傳 `ok: false` 與原因，讓網頁請使用者手動貼上內文：

| 狀況 | 回傳的說明 |
|---|---|
| robots.txt 不允許 | 網站不允許程式讀取，請手動貼上 |
| HTTP 401／403 | 網站拒絕讀取，可能需要登入或阻擋程式（目前天下雜誌就是這樣） |
| HTTP 404 | 找不到這個網頁 |
| 逾時、網路問題 | 連不上網站 |
| 不是網頁（PDF 等） | 這個網址不是網頁 |
| 網頁上沒有文字 | 可能需要登入或內容由 JavaScript 載入 |

讀到了但只有摘要（`partial`）或網站標示付費（`paywalled`）時仍會分析，並附上提醒。
網址不在五個指定來源內時 `source_name` 為「其他網站」。網址指向本機或內部網路（127.0.0.1、192.168.x.x）會拒絕，
避免這個功能被拿來讀內部服務。

## 情緒詞典與版本

**2026-11-14 起，正式詞典以論文字典為底**（台灣財經情緒字典，黃裕烈 2025，7,741 個詞，每個詞 +1 或 −1）。依據：用回補的 9,023 則新聞檢定（見「顯著性檢定」），論文字典的多空報酬差在第 1、3、5、10 日都達 5% 顯著水準（+0.44%、+0.87%、+0.99%、+0.85%），手工詞典四個期間都不顯著；加上手工的個股擴充詞沒有比較好，所以不加。要注意的是「論文字典比手工詞典好」這件事本身還沒達到顯著（配對檢定 p＝0.10～0.28），樣本只有 20 檔個股、約 55 個交易日。原本的手工詞典保留在 `config/lexicon-handmade.json`，只用來比較，不參與正式預測。

正式詞典的設定檔是 [`config/lexicon.json`](config/lexicon.json)：

- `base`：`"remi"` 代表先載入論文字典 `config/remi/dictionary.tsv`
- `sentiment`：只放和論文字典不同的地方，一個詞一行。新增的詞或改過分數的詞寫分數，0 代表停用論文字典裡的那個詞（目前是空的，也就是完全照論文字典）
- `sectors`：產業關鍵字 → 族群（例如 `"HBM": "記憶體"`）

詞典會進版控，隊友共用同一份。資料庫會存每一版的完整快照：
程式每次讀詞典時，只要發現檔案內容跟最新版本不同，就自動建立新版本（第 1 版、第 2 版…）。
之後鎖定預測時，會記錄當時用的是第幾版，事後改詞典也不會影響舊預測。

否定詞（未、不、無…）、加強詞（大幅、強勁…）屬於規則，寫在 `radar/analysis/engine.py` 開頭。

## 已知限制

- 公司短名稱排除規則（見「公司短名稱的排除規則」）是依約 240 則新聞設計的，實際新聞會更複雜；
  發現新的混淆詞時，補進 `config/name_rules.json`。已知會漏掉沒有佐證的冷門兩字公司（例如「信義0.92元」）。
- 產業連動改成只看關鍵字所在句子（見「產業連動只看關鍵字所在句子」）後，像「電子權值股、PCB 族群走強」
  這種句子裡沒有情緒詞的合理連動也會被拿掉；長句子裡剛好有不相干的情緒詞時，仍可能誤觸。
- 分數仍然偏大：重複詞遞減只限制「同一個詞」，長文裡不同的詞照樣累加，78 則新聞中仍有 37 則是「高」。
  理財教學、生活類文章（融資維持率說明、存錢心得）也還是會得到分數，只是不影響個股。
  這兩點打算交給機器學習校正，不再手動調門檻。
- 標題常用空格而不是逗號分隔（爬下來空格已被去掉），「南亞、台玻強勢漲停富喬卻翻黑」三家仍會拿到同樣分數。
- 同一件事的多則新聞各有一筆預測（台積電配息 9 元有十多則），算命中率時會重複計算。
- 2026-10-28 實作排除規則前建立的 6 筆預測已鎖定，保留舊結果；用 `python -m radar.predict --recalc` 可比較。
- 資料表格式有變動時，程式會自動升級舊資料庫（`radar/db.py` 的 `MIGRATIONS`）。
- 天下「今日最新」包含健康、生活等非財經文章，會被收錄但通常分析為中性。
- 經濟日報與 Yahoo 的 robots.txt 允許一般爬蟲，但禁止 AI 爬蟲；這兩個來源由團隊成員在本機試跑確認（2026-10-28）。
  檢查擷取結果可用 `python tools\check_extract.py 網址`。
- 證交所的收盤價 API 偶爾會落後幾天（例如颱風休市後），市值只用來排序，影響不大。

## 顯著性檢定

`run significance --backfill` 檢定「字典判斷利多的個股，之後的表現是否比判斷利空的好」。每個交易日算一次多空報酬差（Fama & MacBeth, 1973），再檢定平均是否不等於 0；觀察期超過 1 天時用 Newey & West (1987) 修正標準誤。另外做論文字典與手工詞典的同日配對檢定。只讀資料庫，不寫入。程式在 `radar/significance.py`。

## 計分方式比較

`run scoring` 用同一部字典（論文字典）比較五種把情緒詞變成利多／利空的方式：加總或情緒指標（正面−負面）÷（正面＋負面），和 0 比或和當天所有個股的中位數比，以及只算負面詞。程式在 `radar/scoring.py`，只讀資料庫。

2026-11-14 用回補的 9,023 則新聞實測：沒有任何一種的命中率贏過「全部猜跌」。「情緒指標／只算負面詞，和當天比」把第 5 日命中率從 42% 提高到 46%（全猜跌 50%），多空報酬差和現行作法差不多；「加總，和當天比」訊號反而消失。差距不夠明確，樣本只有三個月，**所以正式預測沒有改**，等更長的回補資料再確認。

## 新聞過濾比較：行情報導與舊聞

`run novelty` 比較「排除行情報導（標題在描述已發生的漲跌）」「排除舊聞（標題和 2～10 天前的新聞很像，Tetlock 2011）」之後的預測準確度。程式在 `radar/novelty.py`，只讀資料庫。行情報導的判斷用語（`RECAP`）是自己訂的，沒有文獻出處。

2026-11-14 用回補的 9,023 則新聞實測（行情報導 2,668 則、舊聞 1,009 則），**結果和原本的假設相反**：排除行情報導之後多空報酬差變小、多半不再顯著；只留行情報導反而最顯著（現行計分第 1、3、5 日 +0.58%、+0.95%、+1.06%）。也就是目前量到的預測力，主要來自「標題說大漲的個股之後繼續強、說重挫的繼續弱」，比較像股價動能，而不是新聞內容的資訊。排除舊聞沒有一致的效果。已確認這些新聞都有發布時間，盤中與盤後的新聞以當日收盤為基準，沒有偷看到答案。**正式預測沒有改。** 下一步應該檢查：扣掉股價本身的動能之後，情緒分數還有沒有額外的預測力。

## 動能對照：情緒有沒有額外的預測力

`run momentum` 檢查「扣掉股價本身的動能之後，新聞情緒還有沒有預測力」。每個交易日做一次迴歸（Fama & MacBeth, 1973；Newey & West 標準誤）：之後 N 日超額報酬 ＝ a ＋ b1×情緒 ＋ b2×基準日當天超額報酬 ＋ b3×前 5 日超額報酬，解釋變數每天標準化。控制近期報酬的作法同 Tetlock, Saar-Tsechansky & Macskassy (2008)。程式在 `radar/momentum.py`，只讀資料庫。

2026-11-14 用回補的 9,023 則新聞實測（約 7,000 個個股日、49～58 個交易日）：

- 只放情緒（情緒指標）：第 1、3、5 日顯著，高一個標準差之後多 +0.15%、+0.28%、+0.40%。
- 情緒和當日報酬一起放：**情緒的係數變成 −0.07%～+0.10%，四個期間都不顯著（p＝0.33～0.96）**；當日報酬的係數 +0.38%～+0.64%，仍然顯著。

結論：在這三個月的資料裡，情緒分數的預測力可以完全由「當天股價漲跌」解釋，新聞文字沒有帶來額外的資訊。先前「論文字典有顯著區辨力」的結果要這樣理解：字典讀到的主要是股價動能。樣本只有三個月、行情波動大，動能本身是否在其他期間成立也還不知道，需要更長的回補資料再確認。
